Why Agent Blueprint?

Stop reinventing the wheel every session, in every tool

Most AI coding sessions start from scratch: no conventions, no memory, no workflow. Each session reinvents the wheel, and each switch to another tool throws away what the last one learned. Agent Blueprint gives a coding agent one way of working that is the same in every tool: skills that take a feature from design to a pull request, helper prompts for the analysis that benefits from a fresh context, and project documents under docs/ that carry state from one session to the next.
Each unit of engineering work should make subsequent units easier — not harder.

Structured

Skills, helper prompts and quality gates that run in Claude Code, Codex, Antigravity, Grok Build, Pi, Cursor CLI, Hermes and Amp, from one shared skill tree.

Compounding

Every solved problem becomes searchable institutional knowledge. Future plans consult past solutions automatically.

Battle-Tested

19 repos analyzed through source code inspection. Best patterns absorbed, bad patterns documented and rejected.

Pipelines

Four execution modes, the same in every tool

ab-build-pipeline

Supervised

Eight stages with a checkpoint after each, where you approve, change or stop. Research and plan-check helpers feed the plan. Best for guided feature development.

ab-ship-pipeline

Autonomous

No checkpoints. Locks assumptions, plans, executes in dependency-ordered waves, reviews until the findings converge, and writes the commits and the PR body, tracked in state.json.

ab-quick-fix

Fast-Track

For small, well-understood changes under 3 files. Write a failing test, fix it, verify, commit. TDD in its purest form.

run.sh --host <host>

Ship Runner

Drives ab-ship-pipeline unattended through your tool's headless mode: a fresh session per iteration, state in state.json, a secret scan before it pushes and opens the PR. Any of the eight tools.

Helpers, Swarms and Team Work

Four coordination patterns, each for a specific kind of work. Helpers run where the tool has subagents; the session does the work itself where it does not.

ab-review-swarm

Review Swarm

Specialized reviewers in parallel: quality, simplicity and tests always; security, performance, conventions, frontend, architecture, data and schema as the diff calls for. A findings-validator re-checks them and a findings-synthesizer merges them into one P1/P2/P3 report.

ab-deep-research

Research Swarm

Five research helpers work in parallel: best practices, git history, framework docs, codebase context, and past solutions. A research-synthesizer consolidates into one brief.

ab-orchestrate

Team Work

Runs a plan through a task ledger in dependency-ordered waves: one helper per task, each owning its files or its own worktree, and the lead commits. An integration-verifier validates between waves. Works in every tool, one task after another where there are no helpers.

ab-orchestrate

Native Team Extras

When switched on, team work runs on Claude Code Agent Teams (interactive sessions, with quality hooks) or Codex multi_agent_v2 (long-lived helpers that take follow-up tasks). The ledger stays the task list.

Unattended Runs

One ship runner for any of the eight tools, driven by a state file

Large features can exhaust a session's context. When that happens, most setups just stop. Agent Blueprint's ship runner starts a fresh headless session per iteration in whichever tool you name and reads the run's state file between iterations, so work continues in every tool, with or without hooks.

SHIP RUNNER — skills/ab-ship-pipeline/scripts/run.sh --host <host> "<feature>"

A fresh session per iteration

Runs outside the agent in your terminal. Each iteration is a new headless process of the tool you named (claude, codex, agy, grok, pi, cursor-agent, hermes or amp) with a clean context. State persists through git, the plan file and .agent-blueprint/run/state.json.

PUBLISH — the runner, never the agent

Checked before anything leaves the machine

When the state says done, the runner checks that there are new commits since the base it recorded, that the PR body exists at its fixed path, and that the provenance marker names the skill and its version. Then it scans the outgoing range and the PR body for secrets, pushes only to the remote and branch it recorded at preflight, and opens or updates the PR.

The runner records the base, branch and remote itself at preflight; nothing in state.json can move them

The State File Decides

The skill writes .agent-blueprint/run/state.json whole at every stage change: status, stage, iteration, host, driver, a decisions log and a provenance marker. The runner treats every field as untrusted input and never ends a run on text the agent printed, so echoed skill text cannot fake completion.

Least Privilege per Host

Claude Code --permission-mode auto; Codex workspace-write with network on (.git is read-only there, so the skill leaves a commit message and the runner commits); Cursor CLI --force --sandbox enabled; Grok Build --always-approve --sandbox workspace. Pi, Amp and Antigravity can only run unguarded and need --allow-unguarded; there the agent holds your git and gh credentials.

Hooks Where They Exist

In Claude Code and Codex the ship-loop.sh Stop hook keeps an interactive ship session from stopping while the state says running, and stands down under the runner, since a blocked stop would stall every headless iteration. The other six tools have no hooks and need none: the runner and the state file are the guarantee.

When It Stops

The skill sets blocked or needs-human with a reason when it cannot finish; its own ceiling is 20 iterations and the runner's limit is your knob below it. A run is stalled when the stage, the commit history and the team ledger are all unchanged for two iterations. --resume continues from the runner's own record, and the ab-forensics skill reads what a failed run left behind.

Circuit Breakers — Knowing When to Stop

3 consecutive no-progress iterations
5 identical errors in a row
4+ tasks touching the same file
20% WTF-likelihood risk threshold
20 iterations, the skill's hard ceiling

v4.0.0

What's New

Agent Blueprint: the same 53 skills in eight coding CLIs. Claude Code, Codex, Antigravity, Grok Build, Pi, Cursor CLI, Hermes and Amp each get a native manifest or a plain skills copy; helpers, questions and working folders adapt to the host; the ship runner drives an unattended run in any of them. A clean break from claude-code-blueprint v3.8.0, with an upgrade guide and a decision record for the reversal of the single-harness scope.

Eight Hosts, One Skill Tree

A committed manifest per tool that has a plugin system and a plain copy for the rest, all pointing at one skills/ tree. Every skill carries the ab- prefix so a shared skills folder never collides with another pack. install.sh detects your tools and gives each its route.

Helper Prompts, Your Model and Effort

The 29 agents became 30 prompt files inside the skills that use them. No prompt carries a model or an effort tier: helpers inherit the session's choice, and where a tool has no subagents the skill follows the prompt itself and returns the same output shape.

AGENTS.md and .agent-blueprint/

AGENTS.md is the instructions file every host reads, with a one-line CLAUDE.md importing it. Working files moved from .claude/ to .agent-blueprint/; session notes live in docs/context/STATUS.md. Team work merged into ab-orchestrate with a portable ledger and native extras.

Ship Runner, Optional Hooks, New Gates

One runner drives ab-ship-pipeline unattended in any host through state.json. Hooks stay as enhancements for Claude Code and Codex. Portability and manifest gates hold every skill to the rules for all eight hosts, and ab-migrate cleans a v3 project.
