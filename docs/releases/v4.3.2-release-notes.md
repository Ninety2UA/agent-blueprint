# v4.3.2: Agent Blueprint

The body for the GitHub release. A patch release: the build and ship pipelines start helpers only when a change calls for them, and a dependency the user asked for is no longer stopped on a size or necessity flag. No skill, manifest, run-state file or installer flag changes shape.

- ab-requesting-code-review holds the one rule for when a review needs the ab-review-swarm skill: a change that touches authentication, permissions, secrets or money; changes a schema, runs a migration or rewrites stored records; changes something others rely on (a public API, an existing command's flags or output, a file format others read); changes 200 or more lines of code or code in several modules (tests, documentation and the pipeline's own plans and notes do not count); or could fail silently far from the change. Adding an option, an output format or an endpoint without changing existing behaviour is none of these, and neither is reading stored data. ab-executing-plans and ab-build-pipeline's Stage 5 point to that rule instead of naming "auth, money, data or a public contract", which a model read as covering a notes export. ab-review-swarm's description uses the same list.
- The research step in ab-build-pipeline and ab-ship-pipeline starts each of its three helpers only when its question is open: the learnings researcher when `docs/solutions/` has entries, the framework docs researcher when the work adds or upgrades a dependency or uses a framework API new to the code, the codebase context mapper when the change crosses modules or reaches code not yet read. The plan's research notes name each helper skipped and why.
- ab-dependency-management goes ahead without asking when the user's request names the dependency and no Maintenance, License or Security gate shows a red flag. A Necessity or Size flag on that dependency goes into the report with the alternative instead of stopping the run.

Measured with `tests/smoke/eval.sh --compare none` on the build fixture task (a table export for a small notes app, which adds a dependency), Claude Code with Opus 5.5 at `xhigh` and no user settings, one run per arm:

| Build | Runs | Result | Time | Helpers | Cost per run |
|---|---|---|---|---|---|
| 4.3.1 | 2 | both stopped at the 40-minute limit | 40 min | 12 to 14 | about 23M tokens |
| 4.3.2 text, file-count size rule | 2 | 1 pass, 1 stopped at the limit | 20m48s | 3 and 11 | $7.11 for the pass |
| 4.3.2 text, size rule without tests and docs | 2 | 2 pass | 24m10s and 26m53s | 4 and 3 | $7.86 and $8.62 |
| no plugin | 6 | 6 pass | 1m16s to 1m58s | 0 | $0.48 to $0.77 |

The run that stopped counted 12 changed files, 7 of them the pipeline's own plans and notes, and started the swarm. The same changes held 9 to 14 lines of code outside tests, which is why the size rule now counts lines of code.

The build still costs about 12 times a run without the plugin. Helpers take 36 to 50 percent of its tokens, and the tests run 40 to 56 times per build, about half of them with no edit since the previous run.

## Upgrading

A plugin install updates through its tool (`docs/hosts/<host>.md`). A checkout updates with `git pull`, then `bash install.sh` again. A hosted copy updates by the upgrade route in `eve/README.md`: merge the release tag into your clone and redeploy. eve stays at 1.3.0, so open sessions carry over and steps 2 to 5 of that route, which end them, can be skipped.
