# Release checklist: Agent Blueprint v4.0.0

Everything below is the maintainer's to do. The build stopped before each of these steps on purpose: none of them can be undone quietly, and a renamed repository or a published tag reaches every user.

## State when this checklist was written

- Four stacked pull requests, each ready for review with CI green, none merged: #16 (phase 1, into `release/v4`), #17 (phase 2, into phase 1's branch), #18 (phase 3, into phase 2's branch), and the phase 4 pull request (into phase 3's branch).
- `main` serves v3.8.0. Nothing on `release/v4` or the phase branches is installed by any user.
- Every manifest, `package.json` and the seventeen skills that carry `metadata.version` read 4.0.0 on the phase 4 branch.
- The smoke table (`docs/releases/v4.0.0-smoke.md`) holds what could run on the build machine; its "Not yet run" section below lists the rest.

## Before merging

- [ ] Read the four pull requests in order. Each description lists what was verified live and what its review found.
- [ ] Antigravity: set `allowNonWorkspaceAccess` to `true` in `~/.gemini/antigravity-cli/settings.json` (the runner's preflight prints the exact command, which also sets `toolPermission` and `artifactReviewPolicy` to `always-proceed`), install with `agy plugin install <checkout>`, then run `bash tests/smoke/run-smoke.sh --host agy --plugin-dir .`.
- [ ] Grok Build: `grok login`, then `bash tests/smoke/run-smoke.sh --host grok --plugin-dir .`. The shared copy in `~/.agents/skills` already serves Grok.
- [ ] Pi, Hermes and Amp: install each tool, run `bash install.sh` (Hermes also needs the `skills.external_dirs` lines the installer prints), then `bash tests/smoke/run-smoke.sh --host pi,hermes,amp`. Their adapter rows in `skills/ab-ship-pipeline/scripts/hosts.sh` follow the vendor docs and are marked unverified; expect to correct a flag.
- [ ] A cell that fails only because of a vendor bug: add a row to `tests/smoke/scenarios/known-vendor-bugs.tsv` with the upstream link, rerun that cell so it renders `degraded (vendor bug)`, and put the same link in the host's support note under `docs/hosts/` (R28). Any other failure is a release blocker.
- [ ] The Agent Teams check, which only runs interactively: the four steps at the end of `tests/smoke/README.md`.
- [ ] Rerun the whole table once on the final commit: `bash tests/smoke/run-smoke.sh --plugin-dir . --v3-dir <checkout of main at v3.8.0>`. The Definition of Done wants no `fail` cell and all eight hosts covered.
- [ ] Copy each host's row into the `## Smoke status` section of its support note (`docs/hosts/<host>.md`). The notes for the hosts that ran here are already filled in.

## Merging

- [ ] Merge the stack from the bottom: #16 into `release/v4`, then #17, #18 and the phase 4 pull request. GitHub retargets each next pull request to `release/v4` when the branch below it is merged and deleted; check the base before each merge.
- [ ] On `release/v4`, run every gate in `AGENTS.md` § Gates once more, plus `bash tests/runner/run-tests.sh` and `bash tests/smoke/selftest.sh`.
- [ ] Merge `release/v4` into `main`.

## Releasing

- [ ] Tag `v4.0.0` on `main` and publish the GitHub release. `docs/releases/v4.0.0-release-notes.md` is the body.
- [ ] Rename the GitHub repository to `agent-blueprint` (Settings, General). GitHub redirects the old name, so v3 installs keep working.
- [ ] Update the remote in local clones: `git remote set-url origin https://github.com/Ninety2UA/agent-blueprint.git`.
- [ ] Update the repository description, topics and social preview, and the website if it is served from somewhere other than this repository.
- [ ] Update any marketplace listing that names the old repository.

## After the rename (KTD19)

The docs and marketplace files name the final `agent-blueprint` URL, which only exists once the repository is renamed. Until now every install was checked from a local checkout.

- [ ] Claude Code: `claude plugin marketplace add Ninety2UA/agent-blueprint`, then `claude plugin install agent-blueprint@agent-blueprint`; confirm 53 skills.
- [ ] Codex: `codex plugin marketplace add Ninety2UA/agent-blueprint`, then `codex plugin add agent-blueprint@agent-blueprint`, on a machine without the shared copy; confirm each `ab-` skill is listed once.
- [ ] Antigravity: `agy plugin install https://github.com/Ninety2UA/agent-blueprint` (the git-URL form was last verified on 1.0.10 by another project).
- [ ] The copy route from a fresh clone of the new URL: `git clone https://github.com/Ninety2UA/agent-blueprint.git && bash agent-blueprint/install.sh`.
- [ ] An existing v3 install: `/plugin install agent-blueprint@agent-blueprint` adds the new plugin next to the old one, and the session-start warning names `ab-migrate`. Run `ab-migrate` in one v3 project and remove the old plugin as `docs/upgrade/v4.md` describes.
