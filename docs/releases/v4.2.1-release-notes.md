# v4.2.1: Agent Blueprint

The body for the GitHub release. A patch release for the hosted agent: the eight coding CLIs are unchanged except the version number, and every change is in `eve/`.

- **Every change runs the five stages.** A request to change a repository's code or documentation now goes through `ship_pipeline` and its plan, execute, review, verify and ship stages, however small, unless the message names another skill. A question gets an answer with no branch. A bug report finds and verifies its cause first, then runs the stages.
- **A helper's stop ends the run cleanly.** When a helper hits a rate limit, the day's budget or the token cap, the run stops, its branch is pushed with the work done so far, and the web chat, Linear and Telegram say so with the branch. A message the person sends while a helper works no longer ends the run.
- **One branch per chat.** A new request in a chat continues on that chat's branch and open pull request, adds its description between markers, and asks again before it publishes. The agent tells a new request from its wording, and a new request instead of an answer drops the open question.
- **The web chat shows where a run is.** A stage waiting on your answer reads "Waiting for your answer", a stage a helper's stop ended reads "Stopped", and a run that went straight to a pull request says so.
- **The demo counts a visitor's helpers as that visitor's session.** A helper no longer counts as a second visitor, its routes answer only its visitor, and a stop after a stage push still pushes the later commits.

Pushes from a stop reach GitHub on Vercel Sandbox; on Docker and Daytona the hook cannot hand git a token, so a stop there ends unpushed with the reason logged, as before.

## Upgrading

A plugin install updates through its tool (`docs/hosts/<host>.md`). A checkout updates with `git pull`, then `bash install.sh` again. A hosted copy updates by the upgrade route in `eve/README.md`: merge the release tag into your clone and redeploy.
