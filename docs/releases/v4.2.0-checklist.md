# Release checklist: Agent Blueprint v4.2.0

Everything below is the maintainer's to do after the desk that built the hosted option lands. The build stopped before each step on purpose: it committed, published, deployed and spent nothing. These steps need a person, credits, an account or a pushed branch.

## State when this checklist was written

- 2026-10-29, the units of `docs/plans/2026-10-28-2249-feat-agent-blueprint-eve-host-plan.md` up to U12 built in worktrees. Every manifest, `package.json`, `eve/package.json` and the seventeen skills that carry `metadata.version` read 4.2.0, and `scripts/check-manifests.py` now holds `eve/package.json` to the release version too.
- Verified on the build machine, on a clean copy laid out as the product publishes: every gate in `AGENTS.md` § Gates, the site build and its tests, the Eve CI job's commands with the mocked evals on local Docker, and the Codex and Antigravity installs (`docs/releases/v4.2.0-installs.md`).
- Not run: any live model call (the AI Gateway team had no credits), any Vercel Sandbox, Daytona or Railway run, any deployment, and the ship loop, which waits on a decision (below).

## Decisions before the release

- [ ] Choose how `ab-ship-pipeline`'s loop keeps its iteration and stage records on Eve: Eve 0.86.0's workflow steps hold no session state, so the planned loop cannot run as written (U6's notes, NEEDS_CONTEXT 1). The ship cell, the resume eval and upgrade step 7's `resume` eval wait on it. If the loop lands before the tag, drop the sentence about it from the release notes and the host note.
- [ ] Decide whether the eight CLIs' smoke cells run again for 4.2.0. Their skill bodies changed only in the version, and `docs/releases/v4.2.0-smoke.json` holds only Eve's rows. As `tests/smoke/host-notes.py` stands, running it at 4.2.0 rewrites the eight notes' Smoke status sections to the install line alone and drops their 4.1.0 tables; until this is decided, run it on a copy of `docs/hosts/` and take `eve.md` only, as U12 did.
- [ ] Make `tests/smoke/host-notes.py` leave the install line out of Eve's section: Eve is deployed, not installed, so "shows this tool installing Agent Blueprint by its own route" is wrong there. The edit is in U12's notes.

## Before publishing

- [ ] Land the desk with every unit's notes read and each open item settled or carried.
- [ ] Gates on a clean clone of the product folder, laid out as it publishes, with each result recorded: `bash scripts/check-drift.sh`, `python3 scripts/check-manifests.py`, `python3 scripts/check-portability.py`, `python3 scripts/check-skill-collisions.py`, `python3 scripts/sync-shared.py --check`, `python3 eve/scripts/emit-skill-modules.py --check`, `python3 -m unittest discover -s tests/gates`, `bash tests/hooks/run-tests.sh`, `bash tests/runner/run-tests.sh` and `claude plugin validate --strict .claude-plugin/plugin.json`.
- [ ] The Eve CI job's commands, locally, in `eve/` of a copy under your home folder with Docker running and no model key set: `npm ci`, `npx eve build`, `python3 scripts/emit-skill-modules.py --check`, `node scripts/check-skill-count.mjs`, `AB_EVAL_MOCK=1 npx eve eval --tag mock --json --junit out.xml`. Expect every mocked eval passing or skipped with its reason.
- [ ] The site from the product root: `npm --prefix site ci`, `npx astro check` in `site/`, `npm --prefix site run build`, `python3 scripts/check-site.py site/dist`, `node --test 'site/test/**/*.test.mjs'`. The built-page test holds the runner's host radios equal to the README install table's rows.
- [ ] Top up the AI Gateway team, after approving the spend, then run the live cells in `eve/` with `AI_GATEWAY_API_KEY` set and `AB_EVAL_MOCK` unset: `npx eve eval canary --json > "$HOME/eve-live-canary.json"`, `npx eve eval build --json > "$HOME/eve-live-build.json"` and `npx eve eval review --json > "$HOME/eve-live-review.json"`. First move the mocked evals' module-level guard into their test bodies (U9's notes), or no live eval loads.
- [ ] Deploy the demo and run the ship cell against it, once the ship loop and the sample repository exist: `AB_SMOKE_SHIP_REPOSITORY=https://github.com/<owner>/<sample> npx eve eval ship --url https://<demo production address> --json > "$HOME/eve-live-ship.json"`.
- [ ] The deployed Eve copy reports 4.2.0 provenance in the ship cell: on the ship cell's pushed branch, `.agent-blueprint/run/provenance/ab-ship-pipeline.json` reads `"version": "4.2.0"`, and the run's durable record names product 4.2.0 and Eve 0.86.0.
- [ ] Fold the live runs into the smoke record from the product root: `python3 eve/scripts/smoke-to-json.py --version 4.2.0 --input "$HOME/eve-live-canary.json" --input "$HOME/eve-live-build.json" --input "$HOME/eve-live-review.json" --input "$HOME/eve-live-ship.json"`. This also writes `docs/releases/v4.2.0-smoke.md`. Then run `python3 tests/smoke/host-notes.py` as decided above, and check that every one of the fourteen cells in `docs/hosts/eve.md` is labelled.
- [ ] Each deploy route from `eve/README.md` reaches `GET /eve/v1/health`: Vercel, Railway (Daytona and Postgres) and your own server, each after its spend is approved. Record the dates in `RUNBOOK.md`. Railway's button: 2026-11-05.
- [ ] Set the README's release-history date for v4.2.0 to the day of the tag if it is not 2026-10-29.
