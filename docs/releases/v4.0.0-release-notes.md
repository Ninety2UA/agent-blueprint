# v4.0.0 — Agent Blueprint

The body for the GitHub release. `claude-code-blueprint` v3.8.0 becomes **Agent Blueprint v4.0.0**: the same pipelines as one set of 53 skills that installs natively in eight coding CLIs, in a repository renamed `agent-blueprint` (GitHub redirects the old name). This is a clean break; `docs/upgrade/v4.md` walks a v3 project across.

- **Eight hosts** — Claude Code, Codex, Antigravity, Grok Build, Pi, Cursor CLI, Hermes and Amp. Each tool with a plugin system gets a committed manifest that points at the one `skills/` tree; the rest read one shared copy. `install.sh` detects the installed tools and gives each its route. One support note per host is under `docs/hosts/`.
- **`ab-` on every skill** — 53 skills, each named `ab-…`, so a shared skills folder never collides with another pack. `agent-teams` and `team-execution` merged into `ab-orchestrate`; `migrate-to-plugin` became `ab-migrate`. The full map is `docs/upgrade/v4-skill-names.tsv`.
- **Agents became helper prompts** — the 29 agent files are 30 prompt files inside the skills that use them. A helper inherits the session's model and effort, and a skill follows the prompt itself where the tool has no subagents.
- **You choose the model and the effort** — no skill or helper prompt sets either, in any tool. The README has a table of how to set both per host.
- **`AGENTS.md` is the instructions file** — every host reads it; `CLAUDE.md` holds the single line `@AGENTS.md` for Claude Code. The scaffold merges into what a project already has.
- **Working files under `.agent-blueprint/`** — plans in progress, review runs, the team ledger and run state leave `.claude/`. Session notes live in `docs/context/STATUS.md`.
- **Team work in every tool** — `ab-orchestrate` runs a plan through a file ledger in dependency-ordered waves, with helpers where the tool has them and one task after another where it does not. Claude Code Agent Teams and Codex `multi_agent_v2` are optional extras.
- **One ship runner for any host** — `skills/ab-ship-pipeline/scripts/run.sh --host <host> "<feature>"` starts a fresh session per iteration, reads `state.json` between them, and pushes and opens the pull request only after its own secret scan and publish checks. Hosts that can only run unguarded need `--allow-unguarded`.
- **Hooks are optional** — `hooks/claude-code.json` and `hooks/codex.json`. The other six hosts run every pipeline without them.
- **Leaner instructions** — skills state principles with their reasons instead of ALWAYS and NEVER, every `SKILL.md` fits Codex's 8,000-byte limit, and every question names the default an unattended run takes. `docs/upgrade/v4-instruction-rules.md` says where each v3 rule went.
- **New gates** — a portability gate for all eight hosts with an allowlist that only shrinks (it is empty), a manifest gate that holds every version equal, runner tests against a fake host, and a local smoke test (`tests/smoke/`) that runs the pipelines in each installed tool.
- **`ab-migrate`** — cleans a v3 project behind a backup branch and one question, and removes only files the blueprint installed.

## Upgrading

Install v4, run the `ab-migrate` skill in each v3 project, then remove the old plugin: `docs/upgrade/v4.md`. v3 and v4 must not both stay enabled; the session-start hook warns while they are.
