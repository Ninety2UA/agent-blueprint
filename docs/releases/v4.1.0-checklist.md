# Release checklist: Agent Blueprint v4.1.0

Everything below is the maintainer's to do. The build stopped before each step on purpose and did not merge, tag or publish anything. These checks need a person, a pushed branch or the Codex app.

## State when this checklist was written

- Branch `docs/v4.1-plans`, not pushed. Every manifest, `package.json` and the seventeen skills that carry `metadata.version` read 4.1.0. All gates in `AGENTS.md` § Gates pass on the final commit.
- Verified on the build machine: each tool's install by its own route from the local checkout (`docs/releases/v4.1.0-installs.md`), the smoke cells (`docs/releases/v4.1.0-smoke.md`), the five Codex hooks firing in a real session, and `ab-plugin-update` moving a Codex install from 4.0.2 to 4.1.0.
- The maintainer's own Claude Code, Codex, Grok Build, Pi and Hermes installs hold the branch. They were installed from a worktree at `/private/tmp/claude-501/ab-src-410` for the smoke run (Amp reads Claude Code's plugin). § After merge says how to move each back to GitHub.

## Before merging

Push the branch and open the pull request first, so the GitHub forms below can point at it.

- [ ] In a clean profile, run each tool's GitHub install form against the branch where the tool takes a ref, and check that each skill appears once: Codex `codex plugin marketplace add Ninety2UA/agent-blueprint --ref docs/v4.1-plans` then `codex plugin add agent-blueprint@agent-blueprint`; Grok Build `grok plugin install Ninety2UA/agent-blueprint@docs/v4.1-plans`; Cursor CLI `cursor-agent plugin marketplace add https://github.com/Ninety2UA/agent-blueprint --git-ref docs/v4.1-plans`, then `/plugin` in a session.
- [ ] In a profile where Cursor CLI was installed through its own marketplace and `/plugin`, add the Claude Code plugin and run `bash install.sh` again. The installer removes Cursor's marketplace; check `/plugin`, uninstall Cursor's own agent-blueprint if it is still listed, and confirm each skill appears once.
- [ ] **Must pass before merge.** Check the setup step after install in the Codex app. Install from the repository marketplace and confirm the app offers `ab-project-start` in a fresh conversation, in an existing conversation, after updating an existing install, and with a non-empty folder outside any git repository open. In that folder it must show what it would write and ask before writing.
- [ ] In the Codex app, trust the hooks in `/hooks` and confirm the session-start note appears in a new session.
- [ ] Confirm that Codex's `$` picker shows the display names (for example "Project Setup") and that `ab-plugin-update` and `ab-migrate` run only when named.
- [ ] With a design already approved in the conversation, ask any tool to build it. `ab-brainstorming` must not ask for design approval again. The headless smoke cell cannot see an interactive re-ask.
- [ ] In a repository with a function that has no tests, ask for a test-first change to that function. `ab-test-driven-development` adds a test and changes the function in place. It must not delete and rewrite it.
- [ ] Read the pull request description and the final report.

## Merging

- [ ] Merge the pull request into `main` when CI is green.
- [ ] Tag `v4.1.0` on the merge commit and publish the GitHub release with `docs/releases/v4.1.0-release-notes.md` as its body. Vercel deploys the site from `main`.

## After merge

- [ ] In a clean profile, run every tool's GitHub install command once from the README and confirm each skill appears once.
- [ ] Update a real 4.0.2 install with its own (old) `ab-plugin-update`, the path existing users take, and confirm it reaches 4.1.0 with each skill once.
- [ ] Move the maintainer's own installs back to GitHub. Run `bash install.sh` from a fresh clone of `main`; it replaces the worktree registrations for Claude Code, Codex, Grok Build and Pi with the GitHub sources and refreshes the Hermes copy. Then delete the worktree by running `git worktree remove /private/tmp/claude-501/ab-src-410` in the repository.
- [ ] Claude Code keeps older plugin version folders, marked `.orphaned_at`, under `~/.claude/plugins/cache/agent-blueprint/agent-blueprint/` for a while. Amp reads that whole cache, so delete the orphaned folders if Amp should see only 4.1.0 right away.
