# v4.1.0 install record

Plan unit U16 of `docs/plans/2026-10-12-1607-feat-codex-install-and-skill-safety-plan.md`: each of the eight tools installs Agent Blueprint by its own route and sees each skill once, and `ab-plugin-update` moves a real install from 4.0.2 to 4.1.0 (R8, R15, R16; KTD12).

Recorded on 2026-10-12 on macOS, from a clean worktree of the branch at the 4.1.0 bump (`bdf3604`). The branch is not on GitHub yet, so every route ran in its local form (`install.sh --local`, which runs the same per-tool commands with the checkout as the source; KTD11, KTD12). The release checklist runs each GitHub form once after merge.

## Method

For each tool, a fresh profile under the OS temp folder (`HOME` and `CODEX_HOME` pointed there, the macOS keychain linked in so existing sign-ins resolve, nothing written to the real home):

1. `bash install.sh --local --only <tool>` from the worktree.
2. Every folder the tool reads skills from, as the smoke harness lists them (`host_catalog_dirs` in `skills/ab-ship-pipeline/scripts/hosts.sh`), was searched for `ab-*/SKILL.md`, and each of the 53 skills had to appear exactly once.
3. The tool's own listing, where it has one that runs without a model call.
4. A check that no shared `~/.agents/skills` copy was written.

The profile was then deleted. Cursor, Amp and Grok ran a second time with the Claude Code plugin installed in the same profile (`--only claude,<tool>`), since Cursor and Amp read that plugin and Grok does not.

## Updater runtime test

`ab-plugin-update` on a real Codex plugin install, the path an existing user takes:

1. A temp `HOME` and `CODEX_HOME`, with a local marketplace that is a git clone of the branch reset to `8c104f8` (the commit before the 4.1.0 bump, so the updater in it is the new one and the version reads 4.0.2), its upstream the branch itself.
2. `codex plugin marketplace add <clone>` and `codex plugin add agent-blueprint@agent-blueprint` installed 4.0.2.
3. `codex exec ... '$ab-plugin-update Upgrade Agent Blueprint in this Codex install. This is a headless run ...'` with `gpt-6-astra` at `high`.

Result: the skill found the Codex plugin through `codex plugin list --json`, saw a local marketplace that is a git checkout, pulled it fast-forward to `bdf3604` and ran `codex plugin add` again. Afterwards `codex plugin list` reads 4.1.0, the cache holds only the `4.1.0` folder, app-server `skills/list` returns 53 skills from that one folder, and no shared `~/.agents/skills` copy exists. The skill then compared the installed version with `main` on GitHub (still 4.0.2 before merge), reported the mismatch and stopped, as its Step 3 says; after merge the two versions agree.
