# v4.2.0: Agent Blueprint

The body for the GitHub release. A minor release: Agent Blueprint also runs as a hosted agent, beside the eight coding CLIs, and nothing changes for those CLIs except the version.

- **A hosted option on Vercel's Eve framework.** The new `eve/` folder is the blueprint as an agent you deploy to your own Vercel account, Railway or a server you run. You reach it from a web chat, Slack, Linear, Telegram, an MCP client such as Claude Code, or HTTP, name a GitHub repository and a feature, and it works through the same skills to a reviewed pull request. It reads the plugin's `skills/` folder in place, so the hosted agent and the CLIs run the same skill text. The [Hosted page](https://agent-blueprint.dbenger.com/hosted) builds a deploy link from your choices, and [`eve/README.md`](https://github.com/Ninety2UA/agent-blueprint/blob/v4.2.0/eve/README.md) has what to prepare, the three routes, the variables and the upgrade steps.
- **Linear, Telegram and MCP beside the web chat and Slack.** A member of a public Linear team delegates an issue to the agent, and its progress and questions appear in the issue's agent session; the agent mints its own Linear token from your Linear app's client ID and secret. The people you list message a private Telegram bot, and each thread of that chat is its own run. An MCP client such as Claude Code starts and answers runs with a token you choose, and Claude.ai and ChatGPT can sign in through your own identity provider. Each channel admits only the callers you allowed, and during an upgrade none of the three starts new work. A repeated Linear or Telegram delivery starts no second run. Claude Code with the token and Claude.ai with OAuth sign-in each ran to a draft pull request on Vercel and on Railway. Limits: private Linear teams were not checked, attachments are not read, and ChatGPT has not been run live as an MCP client. [`eve/README.md`](https://github.com/Ninety2UA/agent-blueprint/blob/v4.2.0/eve/README.md#after-the-deploy) has the setup, rotation and removal steps.
- **It pushes as a GitHub App you create for one repository.** The agent can reach no repository the App is not installed on. It pushes its own branch after every stage and opens a draft pull request at the end, after a secret scan, and it never pushes from the shell. A change to `.github/workflows` or `.github/actions` needs a person to approve it.
- **One model per role.** The lead, the planner, the builder, the reviewer, the tester, the analyst and the documenter each have a model and a reasoning level through the Vercel AI Gateway, set by a preset that you can change one role at a time. Helpers run on their role's model.
- **Guarded on Vercel, unguarded elsewhere.** On Vercel Sandbox the GitHub token never enters the sandbox. On Docker and Daytona, which Railway and your own server use, each git command reads its token from a file that another process in the sandbox could read while that command runs. [`docs/hosts/eve.md`](https://github.com/Ninety2UA/agent-blueprint/blob/v4.2.0/docs/hosts/eve.md) says what that means, and what a ruleset protects on a private repository.
- **Five skills are degraded there.** `ab-plugin-update`, `ab-forensics`, `ab-browser-testing`, `ab-deployment-verification` and `ab-health-check` load and run, but cannot do all of their work in a hosted sandbox. The host note gives each one's reason. `ab-migrate` and `ab-plugin-update` stay manual-only and load only when you name them.
- **The eight coding CLIs are unchanged.** Every skill, helper prompt and hook they install is the same as in 4.1.1 except the version number. `install.sh --only eve` refuses and points to the Hosted page, because the hosted agent is deployed, not installed.

`ab-ship-pipeline`'s loop of fresh sessions, which the CLIs get from the ship runner, runs on the hosted agent through the `ship_pipeline` tool: one iteration per call, each in a fresh helper, with every stage pushed to the branch as it finishes. A helper or a tool that crashes costs one iteration; on Eve 0.86.0 a failed turn of the lead agent itself, such as a refused model call, ends the session, and the run restarts by hand from the branch it pushed, which keeps every finished stage.

## Upgrading

A plugin install updates through its tool (`docs/hosts/<host>.md`). A checkout updates with `git pull`, then `bash install.sh` again. A hosted copy is new in this release: deploy it by one of the routes in `eve/README.md`. Later releases reach a running copy through the upgrade steps there, which end the open sessions before the new release goes live.
