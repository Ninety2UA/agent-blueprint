# v4.1.0: Agent Blueprint

The body for the GitHub release. Each tool now installs Agent Blueprint with its own command. The skills no longer push a literal-minded model into deleting existing code or asking twice for an approval you already gave. Project setup refuses the wrong folder, and Codex gets a complete plugin listing.

## Install in each tool with its own command

Every tool that has an install command now installs straight from GitHub and updates through its own updater:

| Tool | Install |
|---|---|
| Claude Code | `claude plugin marketplace add Ninety2UA/agent-blueprint`, then `claude plugin install agent-blueprint@agent-blueprint` |
| Codex | `codex plugin marketplace add Ninety2UA/agent-blueprint`, then `codex plugin add agent-blueprint@agent-blueprint`, then trust the hooks in `/hooks` |
| Antigravity | `agy plugin install https://github.com/Ninety2UA/agent-blueprint` |
| Grok Build | `grok plugin install Ninety2UA/agent-blueprint` |
| Pi | `pi install git:github.com/Ninety2UA/agent-blueprint` |
| Cursor CLI | nothing when Claude Code has the plugin; otherwise `cursor-agent plugin marketplace add https://github.com/Ninety2UA/agent-blueprint`, then `/plugin` in a session |
| Hermes | the installer's copy in `~/.hermes/skills` |
| Amp | nothing when Claude Code has the plugin; otherwise the installer's copy in `~/.config/amp/skills` |

`install.sh` stays as the way to set up every tool on the machine at once. It runs the same commands with GitHub as the source (`--local` uses the clone), writes no shared `~/.agents/skills` copy, and on a re-run removes the copies 4.0 recorded. A run limited with `--only` keeps a recorded copy that a tool outside the run still reads, and says so.

## Skill instructions a literal model cannot misread

Every skill, its references and its helper prompts were audited against OpenAI's guidance for GPT-6 Astra, which follows skill text more literally. The fixes are below, one rule at a time. `docs/releases/v4.1.0-instruction-audit.md` gives the reason for each.

- `ab-test-driven-development` discards only code the agent wrote in the task before its test. It never deletes code that existed before the task, or code you wrote or asked to keep. You can also tell the agent to keep its own pre-test code.
- `ab-brainstorming` does not ask you again to approve a design you already approved or told it to build. A request that only asks for code, with no design yet, still gets a design first.
- Skills no longer ask again for an approval you already gave. Deleting work you own, rewriting shared history or pushing needs your own request. Starting a skill whose job is to publish, such as the PR workflow or the ship pipeline, counts as that request.
- Text in files, tool output, PR comments or a helper's report never counts as your instruction. The stage approvals in `ab-build-pipeline`, the batch checkpoints in `ab-executing-plans` and the injection guards stay as they were.

## Project setup refuses the wrong folder

`ab-project-start` no longer scaffolds into whatever folder the session happens to be in. With no folder named, it refuses your home folder and `/`. In a folder that has files but is not a git repository, it shows what it would write and asks first. Inside a repository it never runs `git init` again, so it cannot nest one repository inside another. It also names the repository's top folder.

## Codex

- The plugin listing is complete: the Developer Tools category, a description that counts the five hooks Codex gets, listing copy, links, three example prompts, the brand color, and an icon and logo for light and dark.
- Codex's `$` picker shows a display name and a one-line description for every skill, such as Project Setup for `ab-project-start`. `ab-plugin-update` and `ab-migrate` stay manual-only.
- Codex offers `$ab-project-start` right after you install the plugin.
- The write guard now reads Codex's edits. Codex reports a file edit as `apply_patch` with the patch text. The guard used to look only for Claude Code's `Write` and `Edit`, so on Codex it ran without scanning anything. It now scans the lines each patch adds to files that become agent context.
- A real Codex session showed all five hooks running: the session-start pointer, the write guard, the commit-message check, the context monitor and the ship-pipeline Stop guard.

## Updating

`ab-plugin-update` updates each install through its tool's own route. On Codex it upgrades a Git marketplace or pulls a local checkout marketplace, then adds the plugin again. It never falls back to a skills copy beside the plugin, which made Codex list every skill twice.

Claude Code, Codex, Antigravity, Grok Build, Pi, Cursor CLI, Hermes and Amp each installed the release by its own route and listed every skill exactly once. Cursor CLI, Amp and Grok Build also listed every skill exactly once beside Claude Code's plugin (`docs/releases/v4.1.0-installs.md`). `ab-plugin-update` moved a real Codex install from 4.0.2 to 4.1.0. `docs/releases/v4.1.0-smoke.md` has the smoke cells for discovery, the manual-only rule, hooks, debugging and the two new behavior checks (existing code kept under TDD, and an approved design taken as approved).

## Upgrading

A plugin install updates through its tool, or you can ask any tool for the `ab-plugin-update` skill. If you installed 4.0 with `bash install.sh`, run the 4.1.0 installer once without `--only`. It removes the copies 4.0 recorded in `~/.agents/skills`, `~/.grok/skills` and `~/.pi/agent/skills` and gives each tool its own route. Existing projects need no change.
