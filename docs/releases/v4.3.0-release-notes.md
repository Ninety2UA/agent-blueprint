# v4.3.0: Agent Blueprint

The body for the GitHub release. A minor release for the eight coding CLIs and the hosted agent: no skill was added, renamed or removed, and no public contract changed (manifests, run-state files and installer flags are as in 4.2.1).

- **A missing reviewer is not a clean review.** Every reviewer now says whether it actually reviewed and how many changed files it read. A reviewer that crashed, timed out or never saw the diff is started once more and then listed under "Not reviewed" (any findings it did return are still checked), and the review loop cannot count a round as converged while any reviewer is on that list. A missing security or data-integrity reviewer also lands under Unresolved with a human owner.
- **Reviews run on what they name.** A commit-range review first checks that `HEAD` is the reviewed head and that no file in the range has uncommitted changes, and names that commit. A session reviewing its own work fixes and commits the problems it already knows about first; nothing is edited while the reviewers read.
- **Checks fail closed between waves and in plans.** The integration verifier cannot pass a wave whose report lists issues, regressions or new failures, and a suite that runs zero tests is "nothing verified", not a pass. A plan's own check must read differently before the task than after it; a check that already passes is kept only as a marked guard, and the plan checker blocks a task whose only check already passes. The autonomous loop never ticks a task on a green suite alone when the task had no usable check.
- **Helpers start fresh.** The Helper step asks for a fresh helper, not a fork of the conversation, and waits for its return. Some hosts now fork by default in headless runs, which would hand a helper the whole conversation.
- **Hooks.** The context monitor ignores a helper's tool calls, so the main session's warnings count its own calls only. The session-start hook names a ship-pipeline run that stopped `blocked` or `needs-human`, with its reason (cleaned and capped like every run-state field), and a run-state file that no longer parses.
- **Reports put the gaps first.** The ship pipeline's and the orchestrator's final reports open with what was not done, what was not verified and what changed outside the plan, each "none" when empty, and the ship and loop reports open with a paragraph for a reader who saw none of the run.
- **Smaller fixes.** A pull request can be watched until its checks and automated reviews settle, skipping automated findings on commits since replaced while every person's comment stays until answered; continuing someone else's branch keeps their credit; a ship run's authorization covers the verification its plan needs; implementers stage only their task's files; a mutation check confirms the break landed before trusting the red; solution docs cite code by name, can be marked unverified, and propose a test or convention first; a blocked task in subagent-driven development no longer stops the tasks that do not depend on it; a brainstorm's design doc records the approaches weighed; the frontend reviewer flags one more default look; the forensics and debugging summaries lose their word and token counts in favor of a short summary with detail in the file.
- **Skill-writing guidance.** The authoring references state rules with their reasons instead of capitalized absolutes, test against more than one vendor's models, keep moved rules when detail moves into `references/`, and add two rules: no step that exists for one model, and never edit a skill inside a host's installed copy.
- **Gates.** The portability gate checks `compatibility`, `allowed-tools` and `metadata` value shapes, bans positional placeholders (`$0`, `$1`, `$10`) in SKILL.md, and fails a skill that names one of its bundled scripts without the Bundled scripts snippet. `find-polluter.sh` refuses to run inside its own skill folder.
- **Model and effort notes.** The README and host notes cover Fable 5.2 and Opus 5.5 in Claude Code (both start at `medium`, as do Sonnet 5.5 and Haiku 5.5), the per-helper effort and `CLAUDE_CODE_SUBAGENT_EFFORT`, fast mode on Fable 5.2 and Opus 5.5, Amp's per-thread model selector, and Codex's hook re-review after an update, `exec --trust` and the deprecated `multi_agent` flag. No skill picks a model or an effort level.

The hosted agent picks up the skill changes through its skill modules; its eve version, roster and deploy routes are unchanged.

## Upgrading

A plugin install updates through its tool (`docs/hosts/<host>.md`). A checkout updates with `git pull`, then `bash install.sh` again. A hosted copy updates by the upgrade route in `eve/README.md`: merge the release tag into your clone and redeploy. On Codex, review the plugin's hooks again in `/hooks` after the update.
